## 重要備註

### 志工角色

`volunteer`（志工）角色**未在預設清單中**。若需測試「關懷紀錄建立」功能（志工專屬權限），請：

- **方式一**：進系統 → 後台管理 → 帳號權限管理 → 把任一現有帳號（建議用 `social_02`）加上「志工」角色
- **方式二**：直接讓 `social_01` 或 `social_02` 測試關懷功能（社工人員本就具備關懷紀錄建立權限）

### 申請人帳號

「申請人」帳號**不需要登入系統**，由收件流程自動建立（外部收件或承辦人新增案件時產生）。測試時可用任意身分證字號搭配申請人姓名建立。

## 推薦測試流程（依案件生命週期）

| 步驟 | 帳號 | 操作 |
|---|---|---|
| 1 | `officer_01` | 新增申請案件、上傳必備文件、推進到「家庭訪視」 |
| 2 | `social_01` | 填寫家訪表、推進到「董事審核」 |
| 3 | `chairman_01` | 派組（指派 `board_01` ~ `board_03` 給某個董事組） |
| 4 | `board_01`、`board_02`、`board_03` | 各自登入、輸入核定金額、進行電子簽章 |
| 5 | `chairman_01` 或最後簽章的董事 | 全員簽完後推進到「核銷撥款」 |
| 6 | `accountant_01` | 列印審核意見表 + 領款收據；確認核銷後按「結案」 |
| 7 | `social_01`（或加上志工角色的帳號） | 結案後到該申請人頁面建立關懷紀錄 |
| 8 | `supervisor_01` 或 `chairman_01` | 進「案件統計」檢視通過/不通過分布、drill-down 看細節 |
| 9 | `admin_01` | 後台 → 系統操作紀錄；確認所有操作 audit log |

## 通知測試說明

### 為什麼所有帳號 Email 都一樣？

所有測試帳號的 Email 都設為 `stanley.chen4511@gmail.com`，目的是讓**單一信箱可同時收到不同角色觸發的所有通知**，方便測試人員不必切換多個信箱即可驗證所有通知事件。

### 想分流測試？

如要驗證某個帳號的通知是否獨立送達不同信箱：
1. 進系統 → 後台 → 帳號權限管理
2. 找到該帳號 → 修改 Email 欄位
3. 儲存後該帳號的通知會改寄到新 Email

### LINE 通知測試

要測試 LINE 通知必須：
1. 用該測試帳號登入 → 個人設定 → 產生 LINE 綁定碼
2. 加 LINE bot 為好友
3. 對 bot 傳送 6 位數綁定碼完成綁定
4. 在「通知接收方式」勾選 LINE

完成後該帳號收到的通知會同時送 Email 與 LINE。

## 測試後清空資料

如需清空所有測試案件重新開始：

由系統管理員執行下列 SQL（保留帳號設定，僅清案件相關）：

```sql
DELETE FROM applications WHERE id > 0;
DELETE FROM applicant_care_records;
```

> 此操作會連帶刪除案件文件、家訪、簽章、派組等關聯資料（資料庫使用 cascade 刪除）。
> 帳號、角色、系統設定不會被清除。

如需重新建立測試帳號（例如清庫後）：

```bash
node scripts/seed_users.mjs
```

腳本會自動跳過已存在的帳號、只新建缺的。

## 安全提醒

⚠️ **本帳號清單僅限測試環境使用。正式上線前請：**

1. 變更所有測試帳號的密碼為強密碼，或停用測試帳號
2. 將 `admin_01` 密碼改為僅有特定管理員知道的強密碼
3. 修改所有帳號的 Email 為對應實際使用者的真實信箱
4. 移除或停用未使用的測試帳號
