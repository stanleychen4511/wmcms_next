# WMCMS-11（#86）線上票選會議時間功能 — 可行性評估

> 需求原文：想問問看是否有可能增加線上使用者票選會議時間的功能，因為未來董事會議或是志工會議可能會使用到。

## 結論

**技術上可行，但建議先用現成工具，暫不開發。** 若之後使用頻率高、或需要與系統帳號／通知整合，再排入開發。

## 為什麼可行

系統已具備這個功能需要的大部分基礎：

| 需要的能力 | 系統現況 |
|---|---|
| 參與者名單 | 已有帳號與角色（董事 `board_member`、董事長 `chairman`、志工 `volunteer`…）與董事組別 |
| 邀請與提醒 | 已有 Email 與 LINE 通知派送（WMCMS-5 已修正背景派送問題） |
| 權限控管 | Server Actions 已有依角色守門的慣例 |

## 若要開發，範圍大致如下

1. **資料表**
   - `meeting_polls`：標題、說明、建立者、截止時間、狀態（投票中／已定案／已取消）、定案時段
   - `meeting_poll_options`：候選時段（開始、結束）
   - `meeting_poll_invitees`：受邀者（可一次選「全體董事」「某董事組」「全體志工」或個別帳號）
   - `meeting_poll_responses`：受邀者 × 時段 → 可以／或許／不行
2. **畫面**
   - 建立投票（主管／管理員）：標題、候選時段、邀請對象、截止時間
   - 投票頁（受邀者）：每個時段勾選可以／或許／不行，可修改到截止為止
   - 結果矩陣：人 × 時段，顯示各時段可出席人數，標出最多人可以的時段
   - 定案：選定時段後通知所有受邀者
3. **通知**：發起、截止前提醒、定案結果（沿用現有 LINE／Email 派送與範本管理）
4. **首頁**：「待投票」提示

**估計工作量：約 3–5 個工作天**（含測試與上線 migration）。

## 需要先確認的問題

1. 會議頻率：一年幾次？若只有董事會每季一次，開發效益有限。
2. 參與者是否都有系統帳號？志工會議若有未開帳號的外部志工，就需要「免登入連結」投票，範圍與資安考量都會增加。
3. 是否需要匿名投票、或讓大家看到彼此的選擇？
4. 定案後是否要寄行事曆邀請（.ics）？

## 不開發的替代方案（可立即使用）

| 工具 | 優點 | 缺點 |
|---|---|---|
| **LINE 群組「投票」功能** | 董事／志工多已在 LINE 群組；免費、免安裝、手機操作直覺 | 結果散在聊天室，無系統紀錄 |
| Google 表單 | 免費、可匯出試算表 | 需自行整理時段統計 |
| Doodle / When2meet 等排程工具 | 專為找共同時間設計、結果矩陣清楚 | 外部服務、部分功能需付費 |

## 建議

先以 **LINE 群組投票** 應付董事會與志工會議；若實際使用後發現需要系統內紀錄、與帳號整合或自動提醒，再依上方範圍排入後續 sprint（建議先回答「需要先確認的問題」）。
