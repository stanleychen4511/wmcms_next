## 1. 系統概觀

本系統負責萬美基金會自費醫療補助案件的**收件、審核、家訪、董事審核、核銷、結案**整體流程，同時支援事後關懷追蹤與案件統計分析。

### 補助類別（對應案號第一碼）

| 代號 | 類別 |
|---|---|
| A | 自費醫療補助 |
| B | 臨終安寧自費醫療補助 |
| C | 預立醫療照護諮商補助 |
| D | 醫事人員進修補助 |

案號格式：`{類別}{民國年3碼}{流水號3碼}`，例如 `A115001` = 民國 115 年第 1 件自費醫療補助。

### 案件狀態

| status | 意義 |
|---|---|
| `1` | 審核中（進行中） |
| `2` | 審核未通過（結案） |
| `3` | 待核銷 |
| `4` | 核銷完成（結案） |

### 工作階段（stage）

`admin_review` → `home_visit` → `board_review` → `reimbursement`
（行政初審 → 家庭訪視 → 董事審核 → 核銷撥款）

## 2. 角色與權限

系統有 9 種角色，一個使用者可同時擁有多個角色。

| 角色 | 主要職責 |
|---|---|
| **applicant** 申請人 | 外部使用者，不登入系統（由收件建帳戶） |
| **case_officer** 承辦人員 | 建立案件、文件審核、推進行政初審 |
| **social_worker** 社工人員 | 家訪、填寫家訪表單、關懷追蹤 |
| **supervisor** 主管 | 監督、案件統計、審閱 |
| **accountant** 會計 | 核銷階段處理、列印領款收據 |
| **board_member** 董事 | 董事審核、電子簽章 |
| **chairman** 董事長 | 派組、決策、所有董事權限 |
| **admin** 系統管理員 | 全部權限、帳號管理、系統設定 |
| **volunteer** 志工 | 關懷追蹤 |

### 權限速查表

| 功能 | 可執行角色 |
|---|---|
| 新增案件 | case_officer、admin |
| 申請案件管理 / 查詢 | 全員（依角色顯示不同欄位） |
| 家庭訪視表單編輯 | social_worker、admin |
| 派組（董事分組） | chairman、admin |
| 董事審核 + 簽章 | 被派組的 board_member、chairman |
| 核銷階段文件列印 | accountant、admin |
| 關懷紀錄建立 | volunteer、social_worker |
| 關懷紀錄檢視 | volunteer、social_worker、supervisor、admin |
| 案件統計 | admin、supervisor、chairman、board_member |
| 後台管理（帳號、系統設定） | admin |
| 董事管理專屬設定 | chairman、admin |

## 3. 登入與個人設定

### 登入

1. 開啟系統首頁
2. 輸入帳號與密碼
3. 若帳戶有多個角色，登入後會保留全部權限；某些畫面會顯示角色切換提示

### 個人設定（LINE 綁定 + 通知方式）

首頁 → 右側快速功能 → **「個人設定」**

#### LINE 綁定
1. 按「產生綁定碼」→ 畫面顯示 6 位數字綁定碼（5 分鐘內有效）
2. 點「加 LINE bot 為好友」（或掃 QR 加好友）
3. 在 LINE 對話框輸入剛才的 6 位數碼
4. 收到「綁定成功」訊息即完成

完成後可在下方「通知接收方式」勾選 LINE 作為通知管道。

#### 通知接收方式
勾選 **Email** 和/或 **LINE**（至少一個）。LINE 未綁定時該選項會灰色不可點。

## 4. 案件生命週期

### 流程圖

```
[收件 → apply_at]
        ↓
[行政初審 admin_review]   ← 文件審核；缺件則補件
        ↓ 通過
[家庭訪視 home_visit]      ← 社工填寫家訪表
        ↓ 通過
[董事審核 board_review]    ← 派組 → 全員簽章 → 核定金額
        ↓ 通過
[核銷撥款 reimbursement]   ← 會計列印領款收據 + 系統自動寄 PDF 給申請人
        ↓ 完成
[結案 status='4']
```

**退件/結案路徑**：
- 行政初審或家訪階段審核不通過 → 退回前階段重補 or 結案
- 董事審核「不通過」→ `status='2'` 結案
- 核銷完成 → `status='4'` 結案

### 重要規則

- **案號建立時產生**；同類別同年流水號自動遞增，不可手改
- **申請人 email 必填**（新制）：因核銷階段會自動寄送領款收據
- **退回 board_review 之前的 stage**（例如從 board_review 退回 home_visit）會**清空**：
  - 派組紀錄
  - 董事簽章
  - 董事共同意見（`applications.board_review_comments`）
  - 重新推進回 board_review 時視同全新（需重新派組、重新簽章）

## 5. 常見工作流程

### 5.1 承辦人 — 建立案件

1. 首頁 → **「新增申請案件」**
2. 輸入身分證字號 → **「查詢申請資格」**（系統先檢查是否累積已達上限、是否有未結案）
3. 通過後填寫申請人資訊：姓名、**Email（必填）**、申請類別（A/B/C/D）、申請金額、案件來源（自提/轉介，轉介需選單位）
4. 儲存 → 進入「行政初審」階段
5. 到案件詳情頁上傳必備文件

### 5.2 承辦人 — 案件查詢 / 篩選

首頁 → **「申請案件管理」**

提供篩選：
- 狀態（進行中/結案）
- stage
- 承辦人
- 申請人姓名 / 身分證（模糊比對）
- 申請日期區間

**點列 row** → 進入詳情頁

### 5.3 社工 — 家庭訪視

案件推進到 `home_visit` 階段後，社工：
1. 案件詳情頁 → 切到「家庭訪視」分頁
2. 填寫評估項目（自述病情、對治療態度、家庭互動、補助需求說明等）
3. 儲存 → 推進到「董事審核」

### 5.4 董事長 — 派組

1. 案件進入 `board_review` → 系統依設定決定：
   - **手動派組**（`board_auto_assign='false'`）：chairman 收到「新案件待派組」通知；進後台手動派一個組
   - **自動派組**（`board_auto_assign='true'`）：系統自動選目前案件最少、priority 最小的組別
2. 派組完成 → 組員收到「您所屬組別有新案件待審」通知（Email / LINE）

### 5.5 董事 — 審選 + 簽章

1. 被派組的 board_member 開啟案件詳情 → 「董事審核」
2. 輸入核定金額 + 意見 → 儲存
3. 手寫簽章（觸控/滑鼠）
4. **全組成員都簽完**才能推進到核銷階段
5. 退回或重新指派組別會清空所有簽章（保護審查一致性）

### 5.6 會計 — 核銷撥款

1. 案件進入 `reimbursement` 階段 → **系統自動寄送領款收據 PDF 給申請人**
2. 會計進入案件詳情 → 核銷分頁 → 「文件列印」區塊
3. 三顆按鈕 + 一鍵列印全部：
   - **審核意見表**（含董事電子簽章）
   - **醫療收據**（申請人已上傳的檔案）
   - **領款收據**（基金會 header + 國字大寫金額）
4. 點按鈕會自動叫出瀏覽器列印對話框（可印或存 PDF）
5. 收到申請人寄回的紙本領款收據 → 實體撥款 → 系統標記「核銷完成」結案

### 5.7 退回案件

任何階段都可以「退回」前一階段（附備註）。

**重點**：退回到 `board_review` 之前的階段會**清派組/簽章/審核意見**（為了保證重新進董事審核時是乾淨狀態）。

## 6. 後台管理

admin 角色才可見。**首頁 → 「後台管理工具」**

### 主要分頁

| 分頁 | 功能 |
|---|---|
| 帳號管理 | 建立使用者、指派角色、停用/啟用 |
| 文件類型設定 | 增減必備文件、設定 phase（申請/核銷）、可否延後補件 |
| 轉介單位管理 | 新增合作醫院或單位（決定收件時可選的轉介單位） |
| 董事組別管理 | 建組、指派組員、排序（影響自動派組順序） |
| 檔案儲存位置 | 設定實體檔案櫃位樹狀結構 |
| 公告管理 | 首頁輪播公告的發佈與下架 |
| Banner 管理 | 首頁輪播圖片 |
| 稽核日誌 | 所有關鍵操作的紀錄查詢 |
| 系統參數設定 | 各種閾值、基金會 header 資料 |

### 系統參數設定（重要）

| key | 預設 | 說明 |
|---|---|---|
| `max_apply_amount` | 350000 | 每人累積補助上限（元） |
| `pending_doc_alert_days` | 7 / 14 | 收件後超過幾天缺件才警示 |
| `pending_doc_notification_threshold` | 3 | 累積幾次催件 Email 後首頁提示「考慮不通過結案」 |
| `board_auto_assign` | false | 自動派組開關（true/false toggle） |
| `notification_dispatcher_enabled` | false | 事件通知總開關（**測試完務必開啟**） |
| `line_official_account_id` | (空) | LINE @ID（例 @123abc） |
| `org_full_name` 等 8 個 `org_*` | 已 seed | 基金會基本資料（列印領款收據 header 用） |
| `announcement_new_days` | 7 | 公告顯示「NEW」標籤的天數 |

## 7. 統計與報表

### 案件統計

首頁 → **「案件統計」**（admin / supervisor / chairman / board_member 可見）

1. 選擇日期區間（預設本月 1 日 ~ 今天）
2. 按「查詢」
3. 畫面顯示：
   - **總覽**：通過數 / 不通過數 / 通過率 / 進行中數
   - **依案件類別**：A/B/C/D 各自通過/不通過
   - **依承辦人**：每位 officer 的通過/不通過
   - **依案件來源**：自提 vs 各轉介單位
   - **依月份**：跨月趨勢
4. **點任何數字**（非 0）→ 開 modal 顯示該分類下的案件清單（含最近一筆審核意見 = 可能的「不通過原因」）
5. **下載 CSV**：把整份統計匯出 Excel 相容 CSV（UTF-8 BOM，不會亂碼）

**用途**：幫助主管檢討：
- 哪類別退件率偏高 → 是否該修改收件標準
- 哪位承辦人案量偏載 → 調整分工
- 哪個月份收案異常 → 追查原因

### 狀態定義

| 類別 | status |
|---|---|
| 通過 | `status IN ('3', '4')` |
| 不通過 | `status = '2'` |
| 進行中 | `status = '1'`（**不列入統計分母**） |

## 8. 關懷追蹤

### 檢視 / 建立關懷紀錄

**路徑**：申請案件管理 → 選申請人（含歷史） → **「關懷紀錄」分頁**

| 角色 | 可做動作 |
|---|---|
| volunteer / social_worker | 看 + 新增 + 編輯/刪除**自己**建的紀錄 |
| admin | 看 + 刪除**任何**紀錄（不可編輯他人的） |
| supervisor | 只看 |
| case_officer / 其他 | **看不到這個分頁** |

### 每筆紀錄欄位

- **關懷日期**（必填，預設今天）
- **關懷摘要**（必填，自由文字）
- **媒體雲端連結**（0~N 個）— 把 Google Photos / YouTube / Drive 等 URL 貼進去

**注意**：系統**不收檔**；圖片/影片請傳到外部雲端後把 URL 貼進來。

## 9. 通知系統

### 總開關

`notification_dispatcher_enabled` — 必須為 `'true'` 事件才會真的寄信/推 LINE。
關閉時事件仍會發生（業務不受影響），只是不通知。

### 事件清單

| 事件 | 觸發時機 | 收件人 | 管道 |
|---|---|---|---|
| `case_entered_board_review` | 案件推進到 board_review（手動派組模式） | 全部 chairman | Email + LINE（依個人偏好） |
| `case_assigned_to_board_group` | 派組完成 / 重新派組 | 該組成員 | Email + LINE |
| `case_payment_receipt_to_applicant` | 推進到 reimbursement | 申請人 | **僅 Email（含領款收據 PDF 附件）** |

### 每位使用者的接收方式

使用者 → 個人設定 → **通知接收方式** → 勾選 Email / LINE（至少一個）

**LINE 限制**：需先綁定 LINE 帳號（見 §3）

### 系統 Email 範本

`notification_templates` 表中 5 個以 `email_case_*` / `line_case_*` 開頭的是系統範本：
- 可在後台「通知管理 → 通知範本」編輯 **subject/body**
- **不可改名、不可刪除、不可停用**
- 範本名稱上有「**系統**」標籤

### 缺件提醒

首頁 → case_officer 角色會看到「未補件案件」警示（依 `pending_doc_alert_days` 判定）。
可從警示進入案件；寄 Email 給申請人的記錄會累計 `notification_logs.is_pending_doc_reminder=true`，累積達 `pending_doc_notification_threshold` 後提示「考慮以不通過結案」。

## 10. 常見問題

### Q: 案件推進到 reimbursement 但申請人沒收到領款收據
1. 檢查 `notification_dispatcher_enabled` 是否為 `'true'`
2. 檢查申請人 `users.email` 非空
3. 查 `audit_logs` 的 `notification.payment_receipt_sent` 看 `status`：
   - `sent` = 系統端成功（檢查收件人垃圾信件匣）
   - `failed` = PDF 產生或 SMTP 失敗（看 `errorMessage`）
   - `skipped_no_email` = email 欄位空白

### Q: 我是董事但看不到某件要審的案
- 確認是否被派進該組：後台「董事組別管理」→ 看組員清單
- 若派組重新指派到別組，你就不再看得到（簽章也被清除）

### Q: 不小心推進錯階段怎麼辦
- 用「退回」功能回到前階段；注意退回 board_review 之前會清派組/簽章/意見
- 若是核銷階段推錯 → 聯絡 admin 處理

### Q: 申請人想改 Email
- 重建案件（外部收件或內部建案）時系統會更新既有 applicant 的 email
- 或由 admin 進後台「帳號管理」手動更新

### Q: CSV 匯出開起來亂碼
- 本系統已加 UTF-8 BOM，Excel 應正確識別
- 若仍亂碼：Excel → 匯入資料 → 選 UTF-8 編碼

### Q: 退回案件後重新推進到 board_review，組員還是原來那組嗎？
- 不一定。退回會**清派組**，系統把案件變回「未派組」狀態
- 再次推進 board_review 時：
  - 若 `board_auto_assign='true'` → 系統重新 auto-assign（可能挑到別組）
  - 若 `'false'` → chairman 手動重新派組

### Q: 關懷紀錄的圖片上傳後會儲存在哪？
- **系統不儲存檔案**，只存 URL 字串
- 志工/社工須自行上傳到 Google Photos / Drive / YouTube 等，取 share link 貼進系統

### Q: 統計頁「進行中」的案件數是 5 筆，但總和 approved+rejected 不到所有案件
- 正確行為：**進行中案件（status='1'）不計入通過率分母**
- 這是為了避免用還沒結果的案件稀釋通過率數字

### Q: 系統要開發 / 部署升級注意什麼
- 執行 `psql $DATABASE_URL -f scripts/init_db.sql`（冪等；可重複執行）
- 部署前 `npm run build` 通過
- Vercel function size 限制 50 MB — 本專案含字型約 ~30 MB 尚在安全範圍

## 附錄：專案技術棧速覽

- **前端**：Next.js 16 (App Router) + React 19 + TypeScript 5 + Tailwind CSS 4
- **後端**：Next.js Server Actions + PostgreSQL (Neon Cloud)
- **通知**：Nodemailer (Email) + @line/bot-sdk (LINE Messaging API)
- **PDF**：@react-pdf/renderer + Noto Sans TC 字型
- **加密**：AES-256-CBC（姓名、身分證）+ HMAC-SHA256（密碼、blind index）
- **檔案**：Vercel Blob（申請文件上傳）

**資料庫 Schema 文件**：`database_schema.md`
**開發規範 / Spec**：`openspec/specs/`
**Change 追蹤**：`openspec/changes/`（進行中 / 已歸檔）
